Witty Add-on 1.5.3 – 18 November 2026

Direct GPS reception for Raspberry Pi 5 with Witty Pi 5 and WURB/WIRC.

WURB owns the physical serial receiver while running. Remove GPSD, the Python NMEA converter, socat and virtual GPS ports from this mode. When WURB is stopped or absent, one lightweight fallback reader takes over. Stop that reader before starting WURB; exclusive serial and owner locks prevent simultaneous readers.

Serve homepage GPS status from the existing reader's memory through a local Unix socket, without launching a Python process or connecting to GPSD for each request. Windows uses the same status path.

Explicitly recognise u-blox 6 (1546:01a6), 01a7/01a8 and BU-353 (067b:2303). Retain another unambiguously selected existing USB receiver. Preserve its USB identity and available serial number across port changes. Never guess an unrelated serial device when selection is ambiguous.

Read Waveshare L76X/L86X directly through UART. Probe 4800, 9600, 38400 and 115200 baud without transmitting receiver configuration commands. Allow twelve seconds for checked NMEA during each initial probe, including slow receivers. A healthy connection has no periodic reopen loop.

Validate GP/GN GGA, RMC, ZDA and GSV, checksums, satellite counts and southern/western coordinates. An invalid fix or disconnect invalidates the live position. Expire stale live fixes after twelve seconds; support five- to ten-second receiver cycles. Time synchronisation requires progressing receiver time. Keep fixed UTC offsets, DST rules, saved location selection and manufacturer controls. Back off missing-device retries to at most thirty seconds.

Retain on-demand HTTP activation, idle exit and prior 1.5.2 savings. Other Pi/Witty models keep the legacy GPS path. Existing AllSky exclusions apply.

Install using “Witty Software update” in the existing Windows program. WURB briefly restarts during GPS migration. Back up affected add-on files and configuration under /var/backups/witty-direct-gps and keep a separate WURB GPS source backup. First-time UART activation may require a reboot.

Validation: 80 Python test methods including 33 new GPS/migration checks, and 28 JavaScript tests passed. Exercise the original WURB parser through Linux serial PTYs; status responses through Unix socketpairs; invalid fixes, disconnect, ownership replacement, USB IDs, slow samples, syntax and generated systemd units. Simulate USB/UART/no-GPS migration in an isolated tree. Exclude two unchanged root-only AllSky reboot tests. The test host disallows listening Unix sockets, so actual listener connection setup and real systemd service handovers were not exercised on a Pi.

No hardware test with the user's GPS receivers or Witty, and no measured current or battery-life claim. The entire reported current difference is not confirmed resolved. Publication does not automatically install the update on a Raspberry Pi.
