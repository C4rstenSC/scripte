Version 0.9.8 · Build 3
Changes since 0.9.8 Build 2

Delayed Ethernet release
- Explicitly bring eth0 administratively UP. Restoring NetworkManager management alone left the reported interface DOWN.
- Enable autoconnect on the profile remembered by our delay policy so NetworkManager activates it after link negotiation completes.
- A pending link is no longer reported as an unplugged cable. No additional fixed startup wait is added. Allsky, WURB, Wi-Fi and the hotspot do not wait for Ethernet.
- The separate Ethernet timer and Build 2 terminal fixes remain unchanged.

Release notes in the update terminal
- The update launcher emits complete WITTY-CONTROL blocks, preventing older Windows filters from hiding subsequent release notes and update output.

Validation
- Manually bringing the reported Pi interface UP established carrier after about four seconds and then obtained Ethernet address 192.168.178.181.
- Software tests cover initially DOWN interfaces, pending negotiation, existing connections and profile activation. Automatic behavior on the next boot requires Pi testing.
- The cause of the separately reported hotspot SSH resets remains unresolved.
