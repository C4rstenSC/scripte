Version 0.9.7.1 · Build 7
Changes since 0.9.7.1 Build 6

Ethernet and local startup
- Raspberry Pi 5 Ethernet is released by a separate timer no earlier than 15 seconds after boot and after the ordered local services. The timer does not hold multi-user.target; Allsky can start first.
- Without a cable no lengthy connection attempt is forced. NetworkManager resumes management after release, allowing later cable insertion with autoconnect profiles. Wi-Fi and hotspot startup remain independent.
- The exact temporary 20-second test unit is migrated and its Ethernet profile restored to autoconnect. Updates preserve the current SSH connection; the policy applies on the next boot. Other profile choices are preserved.

Windows interface
- SSH terminal size changes run in the background and coalesce consecutive requests, avoiding UI-thread blocking during window resizing.
- The Allsky selection dialog also suspends terminal input and automatic focus. Inactive or dialog-disabled main windows do not receive automatic terminal focus.

Validation limits
- The user confirmed a post-Allsky reboot with the previous Ethernet delay. The shorter timer and Windows changes still require device testing. The causes of the boot failure and reported frame flicker remain unconfirmed.
