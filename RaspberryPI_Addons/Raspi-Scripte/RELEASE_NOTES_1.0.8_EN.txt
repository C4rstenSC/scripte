Version 1.0.8 · Build 1

Clock check before installation and updates
- Three choices when clocks differ: synchronize and continue; continue without synchronization; cancel. Skipping synchronization attempts the update using the existing clocks. The fixed time zone is retained.

Allsky: observing day and fixed time zone
- Two separate rows at the top of Allsky - Setup show a button and current status, in German and English.
- Optionally assign all new captures to observing days starting at 12:00 noon. Morning captures before noon then belong to the previous day's folder. Disabling restores Allsky's original assignment. Existing files are not changed.
- Optionally apply the fixed UTC offset already selected on the Witty homepage to Allsky's capture process, for example UTC+10:00 without daylight saving time. Disabling returns to the system time zone. A changed Witty offset can be reapplied.
- Running Allsky services are briefly restarted to apply changes; stopped services stay stopped. A failed restart restores the previous configuration. The noon adjustment is reapplied at service start after Allsky updates; unrecognized source layouts are not blindly modified.
- No changes to GPS access, WURB, WIRC, the system clock, RTC or actual location coordinates. Longitude is not changed as a time-zone workaround.

Validation
- Automated tests cover noon/month/year/leap-year boundaries, positive and negative fixed UTC offsets, rollback after failures and German/English browser behavior. Windows application and updater built locally. Physical Raspberry Pi testing remains outstanding.
